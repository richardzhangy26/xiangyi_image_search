# 产品管理展示待归款图片设计

## 背景

Issue #11 已将 2,419 张 Kodo 来源图片迁移为独立 `image_assets`。这些图片没有可靠型号，因此全部保持 `model_number = NULL`；它们可以参与以图搜图，但当前“产品管理”只查询 `products`，页面因此显示“0 个产品”，用户无法在管理界面看到已经迁移的图片。

本设计补齐管理入口，不改变“图片资产独立于商品资料”的领域模型，也不从文件夹或文件名推断型号。

## 方案选择

采用现有产品管理页内的双视图方案：

1. **同页双视图（采用）**：在“产品管理”内增加“待归款图片”和“产品资料”两个页签。用户在同一个工作台查看未归款图片，并在以后有真实型号时关联产品。
2. **独立图片资产页面（不采用）**：职责最纯粹，但入口分散，无法解决用户在产品管理页看不到已导入内容的直接困惑。
3. **自动生成临时产品（不采用）**：能让现有产品表立即出现行，但会制造虚假型号、分类和链接，后续清理及合并成本高。

## 目标

- 产品管理页同时显示产品数与待归款图片数。
- 默认进入“待归款图片”视图，让当前 2,419 张图片立即可见。
- 图片按服务端分页加载，支持按来源相对路径搜索。
- 每项展示私有预览、完整来源相对路径、格式、像素尺寸、文件大小和导入时间。
- 用户可选择一张或多张待归款图片，并关联到一个已经存在的真实产品型号。
- 产品资料页保留现有添加、CSV 导入、编辑、删除和向量索引操作。

## 非目标

- 不从目录、文件名或图片内容推断型号、分类或商品资料。
- 不自动创建临时型号或待完善产品。
- 不在本期实现解除关联、跨型号改绑、归档、永久删除或 OSS 清理。
- 不暴露 OSS Object Key、Bucket、内容哈希或签名 URL。
- 不恢复或依赖旧 `product_images` / 本地 `uploads` 工作流。

## 交互设计

### 页面头部

保留“产品管理”标题，状态区改为两个独立计数：

- `2,419 张待归款图片`
- `0 个产品`

副标题改为“整理待归款图片，并维护已建立型号的产品资料”。顶部保留“添加产品”和“CSV 导入”，使用户可以先建立真实产品；“构建向量索引”保留现有行为。

### 待归款图片

“待归款图片”是默认页签，使用响应式卡片网格：

- 预览区域通过站内 `/api/image-assets/<asset_id>/preview` 加载，浏览器只接触短时 302。
- 主信息显示完整 `source_relative_path`；长路径可换行，并提供原生 title 提示。
- 辅助信息显示 MIME 简称、`宽 × 高`、格式化文件大小和导入时间。
- 卡片支持复选；选中后出现上下文操作条，显示选中数量和“关联型号”。
- 搜索框按来源相对路径过滤；搜索或页码变化时只请求当前页。
- 每页 24 张，提供总数、页码和快速跳转；预览图片启用懒加载。

点击“关联型号”打开弹窗，选择项来自现有产品列表。没有产品时按钮禁用，并提示“请先添加产品或导入 CSV”；这不会阻止用户继续浏览待归款图片。

### 产品资料

“产品资料”页签沿用现有产品表和批量删除行为。产品专属操作仍只在该页签出现；切换页签不丢失待归款图片的搜索条件和当前页，但清空跨页选择，避免误操作。

### 状态与错误

- 图片列表加载失败：保留页面框架，显示错误消息和重试按钮。
- 单张预览失败：卡片显示占位图，不影响其他卡片。
- 关联目标产品不存在：显示“目标型号不存在，请刷新产品列表”。
- 任一资产不存在、已归档或已关联其他型号：整批返回失败且不修改任何资产。
- 关联成功：刷新待归款列表和产品列表，更新两个计数并清空选择。

## 后端接口

### 列出图片资产

`GET /api/image-assets`

查询参数：

- `assignment`: `unassigned | assigned | all`，默认 `unassigned`
- `page`: 正整数，默认 `1`
- `per_page`: `1..100`，默认 `24`
- `search`: 可选，按 `source_relative_path ILIKE` 匹配

只返回 `status = active` 的资产，按 `created_at DESC, id DESC` 稳定排序。

响应：

```json
{
  "assets": [
    {
      "asset_id": "uuid",
      "model_number": null,
      "source_relative_path": "手机挂绳/A47/修改后/2.png",
      "preview_url": "/api/image-assets/uuid/preview",
      "source_size": 58896865,
      "source_mime_type": "image/png",
      "source_width": 6000,
      "source_height": 4000,
      "created_at": "2026-08-02T11:30:00"
    }
  ],
  "total": 2419,
  "page": 1,
  "per_page": 24
}
```

列表表示由专用序列化函数生成，不复用包含 `oss_path`、`preview_oss_path`、`source_bucket` 和 `content_hash` 的内部 `to_dict()`。

### 关联已有型号

`POST /api/image-assets/assign`

请求：

```json
{
  "asset_ids": ["uuid-1", "uuid-2"],
  "model_number": "CS-001"
}
```

规则：

- `asset_ids` 必须包含 `1..100` 个不重复 UUID。
- `model_number` 必须对应已经存在的 `Product`。
- 只允许关联活跃且当前未归款的资产；已关联到同一型号视为幂等成功，已关联到其他型号返回 `409 IMAGE_ASSET_ASSIGNMENT_CONFLICT`。
- 使用单个数据库事务和行锁；任一项不满足条件时整批回滚。
- 成功返回 `assigned_count`、`reused_count` 和 `model_number`。

## 前端边界

- `frontend/src/types/product.ts` 增加安全的图片资产列表类型与分页响应类型。
- `frontend/src/services/productApi.ts` 增加 `getImageAssets()` 和 `assignImageAssets()`；完整 URL 继续通过现有 `getImageUrl()` 解析。
- 将待归款网格拆为独立组件，产品表单和 CSV 弹窗继续由现有 `ProductUpload` 管理，避免进一步扩大单文件职责。
- 延续现有“暖纸工作台”视觉语言：纸张背景、青绿色主操作、琥珀色状态强调、低对比度边框；不引入新 UI 框架或主题。

## 测试与验收

### 后端 TDD

- 列表只返回活跃且符合 `assignment` 的资产，分页与总数正确。
- 中文/空格路径搜索正确。
- 响应不包含 OSS Key、Bucket、哈希或签名 URL。
- 批量关联成功、同型号幂等、目标产品不存在、资产缺失、归档资产和跨型号冲突均有确定响应。
- 批量中任一项失败时所有资产保持原状态。

### 前端与浏览器

- 修改前用当前页面确认不存在“待归款图片”页签，形成红色验收信号。
- TypeScript 与 Vite 生产构建通过。
- 浏览器验证默认展示待归款页签和真实总数；首屏最多请求 24 张预览。
- 验证中文/空格路径、超大图和普通图卡片可见，搜索及分页可用。
- 产品数为 0 时仍可浏览图片，“关联型号”有明确禁用提示。
- 在隔离测试库中新建真实产品后，可把选中图片关联到该型号；成功后待归款计数减少，产品资料中可见关联图片。真实图库的浏览器验收不创建占位产品。

## 完成条件

- 用户打开产品管理即可看到真实迁移图片，不再把“0 个产品”理解为“0 张图片”。
- 数据库不出现自动生成或占位产品。
- 私有 OSS、图片资产独立性和 Issue #12 的旧路径收缩约束保持不变。
