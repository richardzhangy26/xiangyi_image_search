# 向量成功后才创建图片资产

本地导入先持久化为可追踪的图片导入项，在后台生成向量；只有向量成功后才创建可搜索、可归款的图片资产。embedding 暂时不可用时，导入项保留已验证的私有 OSS 原图与预览图并自动或手动重试，但不得以空向量或占位向量进入 `image_assets`。这避免外部模型故障阻塞用户接收图片，也保持“图片资产必然可搜索”的领域约束。

429、网络超时和服务端错误等临时故障采用指数退避，最多自动尝试五次；确定性的图片或向量错误不自动重试。自动重试耗尽后，导入项保留为可诊断的失败状态，允许用户手动重新生成向量且不得重复上传已验证的 OSS 对象。

导入去重遵循来源身份而不是内容唯一性：不同来源路径即使内容相同也分别形成图片资产，但复用同一搜索预览图和向量；相同来源路径与相同内容视为安全重试，相同来源路径与不同内容视为来源冲突且不得自动覆盖。现有手动导入按内容哈希直接跳过不同路径图片的行为必须移除。

图片资产创建前，等待、重试或处理中的导入项允许单项或批量取消；无法中断的在途 embedding 结果必须被丢弃，不得在取消后创建资产。图片资产一旦创建，后续撤销改用回收站生命周期，不再通过导入任务取消。

取消的导入项及其已验证 OSS 暂存对象保留七天，并在窗口内允许恢复导入。窗口结束后才清理当前导入项独占的原图；搜索预览图只有在没有任何图片资产或其他导入项引用时才能清理。该暂存清理规则不适用于已经形成图片资产的回收站内容。

自动重试耗尽的失败导入项保留三十天，展示失败原因、最后尝试时间和剩余窗口；用户可在窗口内手动重试或提前放弃清理。每次手动重试重新计算三十天窗口，到期后按与取消项相同的引用安全规则清理暂存对象。
